01 / 05 · App móvil · Android

SGM Sistema de Gestión Municipal

En producción Código privado

Aplicación para inspectores de una municipalidad de Chaco, que permite labrar actas de infracción en la vía pública con registro fotográfico e imprimirlas en el momento mediante una impresora térmica portátil. Estuve a cargo del desarrollo integral de la aplicación.

Sin duplicados: cada acta lleva una clave única generada en el teléfono, así reenviarla después de un corte de señal no crea otra. Si el servidor rechaza un dato, el acta vuelve al inspector en el paso a corregir.

  • Offline-first: base local con Drift/SQLite, borradores recuperables, bandeja de envíos y sincronización de catálogos con la API .NET
  • Cámara de evidencia propia, envío multipart de fotos e impresión de tickets con código de barras y QR por Bluetooth
  • Actualización in-app del APK, entornos aislados por flavor, sesión segura y más de 540 tests de unidad, widgets y contratos
  • Flutter
  • Dart
  • BLoC / Cubit
  • Drift · SQLite
  • API REST · .NET
  • Bluetooth ESC/POS
  • FCM

02 / 05 · Apps móviles · Android & iOS

Tu Remis SP Pasajeros y conductores

Publicada Código privado

Ecosistema de dos aplicaciones, una para pasajeros y otra para conductores, que permite solicitar un remis, seguir el viaje en el mapa y compartirlo en tiempo real. Incluye además un sistema SOS que se comunica con un número de emergencia.

Aceptar un viaje: es una transacción de Firestore que solo lo asigna si sigue pendiente; si otro conductor lo tomó antes, la app le avisa que ya fue tomado.

  • Viajes, estados y ubicación del conductor sincronizados en vivo con Cloud Firestore
  • Seguimiento del viaje compartible mediante enlace: deep links, Cloud Function de redirección y página en Firebase Hosting
  • Inicio de sesión por email con verificación por SMS, notificaciones locales y actualización forzada con Remote Config
  • Flutter

  • Firebase

  • Google Maps
  • Remote Config

Cómo trabajo

Del relevamiento a producción.

Las aplicaciones que desarrollo se utilizan en la vía pública, en mostradores y en oficinas, muchas veces con conectividad limitada. Por eso priorizo el diseño de los datos y el comportamiento del sistema ante fallas.

  1. 01

    Relevamiento

    Me reúno con los usuarios finales (inspectores, conductores, personal de atención al público) para comprender el flujo de trabajo real antes de comenzar el desarrollo.

  2. 02

    Datos y contratos

    Defino el modelo de datos, los contratos con el backend y la estrategia offline: base local, cola de envíos y reglas de sincronización.

  3. 03

    Desarrollo con tests

    Gestión de estado con BLoC/Cubit y tests de unidad, widgets y contratos. En SGM, la app municipal, son más de 540.

  4. 04

    Entrega y traspaso

    Builds por entorno, actualizaciones dentro de la aplicación y documentación de traspaso, para que el equipo que sigue pueda mantener el sistema sin depender de mí.

Desarrollo asistido por IA, con criterio

Utilizo Claude Code para auditar código, escribir tests y documentar. Antes de cada entrega, todos los cambios pasan por mi revisión, conforme a buenas prácticas y estándares de programación, y por la suite de tests.
